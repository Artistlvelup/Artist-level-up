# Cloudflare R2 upload-intent configuration

This guide applies only to the isolated V101 migration Worker. It does not change the live V101 page or deploy the Worker.

## Worker configuration

The authenticated route `POST /api/me/videos/upload-intent` now creates a five-minute S3-compatible presigned PUT URL for the R2 bucket. It requires an authenticated session and an active, non-suspended artist account. The object key is generated by the Worker under that artist's own prefix; the browser cannot choose another artist's prefix.

Configure these Worker variables/secrets in Cloudflare:

- `CLOUDFLARE_ACCOUNT_ID`: the Cloudflare account ID.
- `R2_BUCKET`: `artist-level-up-videos`.
- `R2_PUBLIC_BASE_URL`: the HTTPS public delivery base URL for this bucket, with no trailing slash. Use the verified R2 custom domain, not a guessed URL.
- `R2_ACCESS_KEY_ID`: an R2 S3 API token access key ID; store as a secret/secret binding.
- `R2_SECRET_ACCESS_KEY`: its secret access key; store as a Worker secret.
- Existing `SESSION_PEPPER` and `ALLOWED_ORIGINS` remain required.

Create a dedicated R2 token with the minimum required bucket permissions for the target bucket. Do not reuse the Cloudflare account API token used for D1 deployment. Never place the R2 secret access key in GitHub source, browser HTML, or a public repository.

## Request

Send an authenticated JSON request to `POST /api/me/videos/upload-intent`:

```json
{
  "purpose": "video",
  "filename": "performance.mp4",
  "contentType": "video/mp4",
  "size": 10485760
}
```

For a thumbnail, use `purpose: "thumbnail"`, an allowed image MIME type, and a size no greater than 10 MiB. Video size is limited to 5 GiB. The response contains `uploadUrl`, `publicUrl`, `objectKey`, `contentType`, and `expiresIn`. Upload the file with a direct HTTP PUT to `uploadUrl` and set the exact `Content-Type` value supplied in the request. The URL expires after five minutes.

Allowed video MIME types: MP4, WebM, QuickTime, AVI, Matroska and M4V. Allowed thumbnail types: JPEG, PNG and WebP.

## R2 bucket CORS

Configure the bucket CORS policy to allow only the exact production web origins and the required browser PUT request. Allow the `PUT` method and `Content-Type` request header; expose only response headers the browser actually needs. Do not use wildcard origins for authenticated uploads.

## Important limitations

- This endpoint only authorizes an object upload. It does not yet create an `artist_videos` row, verify that the upload completed, or implement deletion/moderation.
- A five-minute presigned URL is bearer access until it expires; do not log or share it.
- The current page has an inconsistent 5 GB versus 50 MB message. Resolve that in a separately reviewed V101 integration after API tests pass.
- The current prototype has not been run against a real R2 bucket. Verify signature compatibility, bucket CORS, public delivery, HTTP Range playback, object size limits and content-type behaviour in a non-production test bucket before cutover.
- No live deployment, D1 migration apply, or V101 HTML change is part of this commit.
